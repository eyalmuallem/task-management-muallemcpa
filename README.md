# מערכת ניהול משימות — אורי מועלם ושות'

מערכת סטטית המיועדת להעלאה ישירה ל-GitHub Pages. אין צורך ב-Node.js, ב-npm או בתהליך Build.

## מבנה הפרויקט

- `index.html` — מבנה הממשק.
- `assets/css/styles.css` — עיצוב מלא ורספונסיבי.
- `assets/js/app.js` — לוגיקת המערכת, המשימות ולוחות השנה.
- `assets/js/firebase.js` — חיבור Firebase הקיים.
- `assets/js/utils.js` — פונקציות עזר.

## לוח שנה

- למנהל יש לוח שנה עם שלושה מסננים:
  - משימות שאני נתתי לעובדים.
  - משימות כל העובדים.
  - משימות לפי עובד נבחר.
- לעובד יש לוח שנה אישי המציג משימות שהוקצו לו ומשימות שיצר לעצמו.
- צבעי המשימות בלוח השנה:
  - ירוק — נותרו יותר מיום עד תאריך היעד.
  - צהוב — תאריך היעד מחר.
  - אדום — תאריך היעד היום או שהמשימה באיחור.
  - אפור — מופע שהושלם.
- עובד יכול ליצור לעצמו משימה לא חזרתית, חודשית או דו-חודשית.
- השלמת מחזור של משימה חזרתית שומרת את המועד שהושלם ומקדמת את תאריך היעד למועד הבא.

## תאימות למסד הנתונים הקיים

הפרויקט ממשיך להשתמש בדיוק באותו Firebase ובאותם אוספים:

- `users`
- `tasks`

לא נדרש שינוי ב-Firebase Authentication, ב-Firestore או בכללי האבטחה. לא נוספו אוספים חדשים.

למסמכי משימות חדשות עשויים להתווסף שדות אופציונליים בלבד:

- `clientName`
- `recurrenceType`
- `recurrenceDay`
- `completedOccurrences`

Firestore אינו דורש שינוי סכימה, ומשימות קיימות שאין בהן שדות אלו ממשיכות לעבוד כמשימות רגילות ולא חזרתיות.

## העלאה ל-GitHub Pages

יש להעלות את כל תוכן התיקייה לשורש ה-Repository, כולל תיקיית `assets`. המבנה בשורש צריך להיות:

```text
assets/
README.md
index.html
```

## הרצה מקומית

מומלץ להריץ דרך שרת מקומי ולא באמצעות פתיחה ישירה של `index.html`, משום שהמערכת משתמשת ב-JavaScript Modules.

```bash
python3 -m http.server 5500
```

לאחר מכן לפתוח בדפדפן:

```text
http://localhost:5500
```

## הערה לגבי הסרת עובדים

הסרת עובד דרך הממשק מוחקת את מסמך המשתמש ואת המשימות שלו מ-Firestore. מחיקת חשבון מ-Firebase Authentication דורשת Firebase Admin SDK ואינה מתבצעת מאתר סטטי.
